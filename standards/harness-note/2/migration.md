# Adoption and corpus migration

Order: WorkflowX specification/tools/corpus, then agentX reader/writer/execution/index, then JanusX blueprint and engineering Chat. Do not bulk-sync new rules into unsupported adopters. A profile pin is an explicit format contract, not a claim that installed runtime packages support it.

Keep standards/harness-note/1 sealed. A repository adopts v2 only with a capable writer, a documented inventory and explicit version/digest pin. Old assets remain classified and readable as historical or deferred sources; never count unsupported files as validated v2. A missing migration/parse tool does not turn a failed check into a pass.

Inventory before edits: original path, ID if any, raw-source hash, current purpose, target module/path and disposition. Preserve IDs and created dates for continuing subjects. Classify initiative by actual content. Do not invent Task receipts or historic timestamps. Preserve unrelated dirty/untracked sources; record exact deferrals.

Migrate old Notes as a distinct work item before final corpus parsing/validation: group by actual module responsibility, introduce one entry per module, rewrite stale current explanations, archive/absorb/delete obsolete material with reasons, and repair live links/code references. Retain necessary provenance through Git and the migration record, not embedded full-document backups.

A Task's v1 historical contract/evidence remains v1 evidence. Conversion to v2 requires explicit reassessment before any new run; never rehash old receipts to claim they covered a changed contract. Source hashes used by wiki pages are not silently refreshed.

After migration validate schema, unique module entries/IDs, directory ownership, local links/AC references, cycles, timestamps and index coverage. Report protected legacy/foreign files separately. Cross-repository unresolved refs remain explicit until selected checkouts are available.

agentX acceptance additionally proves read/edit/script tools, index invalidation, transactions, mode/review obligations and fresh-session handoff. JanusX acceptance proves module-only initial blueprint with planning states, expand/detail/return, common wiki reads and engineering Chat integration. Each phase records its own evidence rather than claiming downstream checks.
