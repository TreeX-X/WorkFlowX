# xarch architect-workspace scaffold command

## Problem

An architect workspace is an ordinary git repository with `.agents/harness.json` plus `notes/planning/` templates, but it had no deterministic trigger: each establishment was hand-assembled through prompts, so steps were skipped, dirty trees were committed over, and existing identities were overwritten. The two surfaces also lacked a shared definition, inviting Claude/Codex drift.

## Decision

`xarch <dir> [--name <name>] [--with-codeowners]` runs Main-Agent-direct with six fail-fast steps: git init (reuse existing repo, stop on dirty tree), `.agents/harness.json` (schemaVersion 1 plus fresh UUID repoId plus frozen workflowx profile digest, verify-only if present), `notes/planning/` templates (`project.md` plus one `module-example.md`, kind initiative, frozen shape, no views/), CODEOWNERS plus README, registration through the existing workspace.create chain, and projection verification (projectView readable, invalid not increased). Landed as `.claude/commands/xarch.md`, one `AGENTS.md` prefix row, and identical `xarch` blocks plus Commands rows in both `orchestrateX` copies. Module splits, interface names, and primary bindings stay in chat with changeset two-layer approval; post-handoff note edits go through harness transactions plus expectedHash plus approval. P1-frozen scope holds: no new kinds, fields, or views, so the sealed standard and its digest are untouched.

## Alternatives considered

- Prompt-assembled establishment — strongest case is zero new files, but steps get skipped and identities overwritten with no verifiable gate; rejected in favor of the deterministic command with per-step checks.
- Full bus-payload delegation mode — strongest case is uniformity with xdel/xflow, but scaffolding has no task note, no dispatch target, and no iteration; a payload contract would be empty ceremony, so xarch stays direct like xdo.
- Do nothing / reuse — keep hand-building workspaces; rejected because unrepeatable setup is exactly where shared-project identity corruption starts.

## Consequences

- **Gains**: every architect workspace starts from the same six verified steps on both surfaces; sync tooling converges adopters without a standard release.
- **Costs and limits**: command files and `AGENTS.md` are per-repo owned files outside the managed pairs, so each adopter carries its own copy until the sync scope is extended; promotion of anything structural still needs the version track. Revisit when the first real scaffold exposes a missing guard.
