# proseX

Write for a reader without the conversation: responsibilities, conditions, consequences and necessary reasons. Prefer connected plain prose; use tables/lists for genuinely comparable or sequential information.

Current design and implemented decisions state present facts. Planned sections clearly state future intent or unknowns. Tasks describe current progress and evidence, not a growing conversation log.

Keep each fact in its owning document; related documents give enough context and link for detail. A module entry can explain the whole system without copying all child details. Length follows the subject, not a quota.

Decisions explain the problem, choice, credible alternatives (including reuse/do nothing), costs and revisit conditions. Do not claim verification that did not run. Preserve fixed references and stable acceptance IDs.

Summarize changes and actual validation with material gaps. Commit messages describe the change and relevant Note paths. Remove obsolete wording and duplicated process history instead of appending another dated explanation.
